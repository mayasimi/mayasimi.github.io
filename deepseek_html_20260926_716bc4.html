Enterprise Security Monitoring Lab

Wazuh · Ubuntu Server · Windows · SIEM · Filebeat

View Repository

Problem

Security events were being generated across Windows and Linux systems with no central place to collect, correlate or review them. There was no visibility into failed logons, privilege changes or suspicious process activity.

What I did

  • Deployed and hardened an Ubuntu Server host
  • Configured SSH access and firewall rules
  • Installed and configured the Wazuh manager
  • Connected a Windows endpoint via the Wazuh agent
  • Configured event collection and log ingestion
  • Enabled archived logs for retrospective analysis
  • Configured Filebeat to ship alerts into the dashboard
  • Investigated real security events and tuned noisy rules

What I learned

Centralised logging is only useful if the rules are tuned. Getting Wazuh running took a day; making its alerts actually meaningful took far longer — and that tuning work is where the real analyst skill lives.

Phishing Investigation

Email Analysis · IOC Enrichment · Verdict

Scenario

A user reported a suspicious email asking them to re-authenticate their account. The task was to determine whether it represented a legitimate threat and what action should follow.

Investigation

  • Examined full email headers and authentication results
  • Analysed sender domain, SPF, DKIM and DMARC outcomes
  • Extracted and sandboxed the embedded URL
  • Reviewed indicators against threat intelligence sources
  • Determined malicious vs. benign characteristics
  • Documented findings in an incident report format

Analyst Verdict

The sender domain failed DMARC alignment and the embedded URL redirected through a typo-squatted domain to a credential-harvesting page. Classified as malicious phishing. Recommended action: block the sender domain, block the URL at the gateway, force a password reset for the recipient, and issue an awareness notice to the wider team.

Takeaway

Header analysis alone would not have caught this — the redirect chain was the deciding evidence. Always follow the URL, not just the sender.

PCAP Investigation

Network Forensics · Wireshark · Host Identification

Objective

Analyse network traffic to identify suspicious communication and determine the potentially compromised host on the network.

Method

  • Loaded the capture and reviewed protocol hierarchy
  • Filtered for DNS queries and identified anomalous lookups
  • Traced source and destination IP pairs
  • Inspected suspicious traffic for beaconing patterns
  • Correlated findings back to a single internal host

Findings

One internal host was making regular, evenly-spaced DNS requests to an unusual external domain, followed by periodic HTTP POST traffic to the same infrastructure — a pattern consistent with command-and-control beaconing.

Recommended Action

Isolate the host, capture memory and disk for forensic review, block the destination infrastructure at the perimeter, and hunt for the same indicators across the rest of the estate.

ISO 27001 · Control Review · Risk Assessment

Objective

Identify gaps between the organisation's current security practices and the selected framework, then translate those gaps into a risk- ranked remediation plan for management.

Methodology

Sample Findings

Control Current State Gap Risk Recommendation

Outcome

Findings were consolidated into a risk register and presented to management with owners, target dates and a suggested remediation sequence based on risk severity.
